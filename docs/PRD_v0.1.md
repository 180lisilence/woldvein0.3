**文档版本**：v0.3 | **更新日期**：2026-09-13 | **产品版本**：v0.3 MVP

## 一、需求与规划

### 1.1 目标用户

| 用户类型 | 特征 | 核心需求 |
|----------|------|----------|
| 休闲玩家 | 想体验游戏内容但不想花时间刷资源 | 一键满资源、快速解锁建筑 |
| 城建爱好者 | 想自由建造不受等级/资源限制 | 创造模式、全建筑解锁、无限资源 |
| 测试/Mod开发者 | 需要快速切换游戏状态做测试 | 存档编辑、热键、参数微调 |
| 手残/时间少玩家 | 打不过挑战模式 | 无敌资源、满级鸿业、跳过限制 |

### 1.2 使用场景

1. **启动游戏后**：打开修改器 → 检测游戏进程 → 一键开启创造模式
2. **游戏中**：通过热键快速加资源（Ctrl+F1~F9），无需切出游戏
3. **存档管理**：打开存档编辑器 → 解密存档 → 修改参数 → 加密回写 → 进游戏验证
4. **多存档切换**：备份/恢复不同进度的存档

### 1.3 解决的问题

- 游戏资源获取慢，城建需要大量资源积累
- 鸿业等级限制建筑/功能解锁，前期可玩内容少
- 存档损坏/卡加载无法修复
- 现有修改器分散（3个独立工具），用户体验割裂

### 1.4 竞品分析

| 竞品 | 优势 | 劣势 |
|------|------|------|
| 风灵月影修改器 | 通用、热键多 | 不支持本游戏、无创造模式、无存档编辑 |
| Cheat Engine | 强大、可搜内存 | 需要手动找地址、门槛高、易崩溃 |
| 游戏内置控制台 | 原生 | 功能有限、需要解锁 |
| **本产品** | **专为游戏定制、创造模式、存档编辑、一体化** | **仅支持单游戏** |

### 1.5 商业模式

- **v0.3-v1.0**：免费开源，个人使用
- **v2.0+**：可选付费高级版（云存档同步、Mod市场、自动更新）
- **盈利方式**：捐赠 / 高级版订阅 / Mod平台抽成

### 1.6 功能清单与优先级

| 优先级 | 功能模块 | 子功能 | v0.3 |
|--------|----------|--------|------|
| P0 | 游戏检测 | 自动检测游戏进程、PID显示 | ✅ |
| P0 | 资源修改 | 9种资源+100万、幸福度最大、知名度+1万 | ✅ |
| P0 | 创造模式 | 鸿业满级、全建筑解锁、无限资源、升级无限制 | ✅ |
| P0 | 热键系统 | Ctrl+F1~F12、可配置 | ✅ |
| P1 | 存档编辑器 | 解密/查看/修改/加密回写 | ✅ |
| P1 | 游戏启动 | 一键启动游戏（Steam协议） | ✅ |
| P2 | 配置管理 | 保存/加载用户配置 | ✅ |
| P2 | 日志系统 | 操作日志、错误日志 | ✅ |

### 1.7 MVP（最小可行产品）定义

**v0.3 MVP 必须包含**：
1. 游戏进程自动检测与手动选择
2. 资源修改面板（9种资源一键+100万 + 幸福度最大 + 知名度+1万）
3. 创造模式一键开关（鸿业满级 + 全建筑解锁 + 无限资源 + 升级无限制）
4. 全局热键支持（Ctrl+F1~F12）
5. 存档基础编辑（解密查看 + 加密回写）
6. 操作日志显示

**验收标准**：
- [ ] 启动修改器后能自动检测到游戏进程
- [ ] 点击"金钱+100万"后游戏内金钱确实增加
- [ ] 点击"开启创造模式"后：鸿业等级=14、所有建筑可建造、建造不扣资源、建筑可升级到最高级
- [ ] 热键 Ctrl+F1 在游戏内生效（金钱+100万）
- [ ] 存档能成功解密为SQLite并查看，修改后能加密回写且游戏能加载
- [ ] 关闭创造模式后游戏恢复原版逻辑
- [ ] 所有操作有日志记录

## 三、技术组成

### 3.1 客户端架构

```
┌─────────────────────────────────────────┐
│              GUI 层 (tkinter)            │
│  主窗口 / 标签页 / 资源面板 / 创造模式   │
├─────────────────────────────────────────┤
│            业务逻辑层 (Python)            │
│  资源修改 / 创造模式 / 存档编辑 / 热键    │
├─────────────────────────────────────────┤
│            注入通信层 (Python+C)          │
│  DLL注入 / lua_pcall Hook / Lua执行      │
├─────────────────────────────────────────┤
│              游戏进程 (BalladsOfHongye)   │
│         Lua5X64.dll + 游戏逻辑            │
└─────────────────────────────────────────┘
```

### 3.2 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|
| GUI | Python 3 + tkinter | 系统自带，无需额外依赖，打包体积小 |
| DLL注入 | Python ctypes + C DLL | 复用现有 CreativeMode.dll 注入框架 |
| Lua执行 | inline-hook lua_pcall | 在游戏主线程执行Lua代码 |
| 存档编辑 | Python sqlite3 + 自研加解密 | 复用 fix_saves.py 加解密算法 |
| 热键 | Python keyboard 库 / win32api | 全局热键监听 |
| 打包 | PyInstaller | 打包为 onedir 目录（非单文件） |

### 3.3 核心技术方案

**DLL注入与Lua执行**：
1. Python 通过 OpenProcess + VirtualAllocEx + WriteProcessMemory + CreateRemoteThread 注入 DLL
2. DLL 内 inline-hook Lua5X64.dll 的 lua_pcall 函数
3. 在 hook 回调中，通过线程安全队列执行 Python 端传入的 Lua 代码
4. Lua 代码直接操作游戏全局变量（g_camp、g_BuildingWorldModule 等）

**创造模式实现**：
- 资源不扣：hook LBuildingMgr.ConsumeResource / LBaseBlock.ModifySourceValue，创造模式下跳过扣减
- 全建筑解锁：调用 scheme:SetBuildingCardState(allCards, true) + AddOtherBuildings + UI刷新
- 鸿业满级：hook LCampBoom.IsSatisfied/GetBoom + 直接 setBoom(14) + UpdateHistoryMaxBoomLevel()
- 升级无限制：hook CheckCanUpgradeBuilding/GetAdvancedUpgrade

**存档加解密**：
- .boh 文件 = SQLite 数据库（无加密头，整体为标准 SQLite 格式）
- userdata 表包含 path + buffer 字段，buffer 为加密的 JSON 数据
- buffer 加密：ROR3 循环右移3位 + 每16字节反转
- buffer 解密：每16字节反转 + ROL3 循环左移3位
- 编辑：用 sqlite3 打开 .boh，修改 userdata 表中对应条目的 buffer
- 加密：修改后重新加密 buffer + 写回 SQLite

### 3.4 数据库/配置

- **用户配置**：JSON 文件（`config.json`），保存热键映射、窗口位置、上次使用设置
- **日志**：文本文件（`logs/trainer_YYYYMMDD.log`）
- **存档备份**：修改存档前自动备份到 `backups/`

### 3.5 技术文档

- 架构图：见 §3.1
- API 文档：Lua 执行接口、存档编辑接口（代码内 docstring）
- 部署文档：见 §五 开发流程

- 修复优先级：P0 立即修复，P1 当日修复，P2 本周修复，P3 下个版本

### 6.3 质量门禁

v0.3 发布前必须通过：
- [ ] 所有 P0/P1 Bug 已修复

- [ ] 不修改游戏磁盘任何文件
